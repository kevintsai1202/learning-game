# 更新通知（有新版時提醒並更新，避免有人一直停在舊畫面）

> 狀態：**完成，2026-10-13 02:57 上線**，實作紀錄見第 4 節。上線後查證：GitHub Pages 的 `version.json` 版本號是提交編號前 12 碼（`39c40d45a8c8`），Zeabur 是建置時間（`t1791831307215`）、`Cache-Control: no-cache`。使用者需求：「是否能加上更新通知，以後更新都通知，避免有人還在舊畫面上」。決定：提示＋安全時自動更新；老師頁、家長頁也要通知（大人的頁面只提示、不自動重新整理）。

## 1. 怎麼知道有新版

- 每次建置產生一個**版本號**（有 git 提交編號就用它，沒有就用建置時間；GitHub Pages 與 Zeabur 各自建置，各自比對自己的），寫進網頁（`__BUILD_ID__`），同時輸出一個小檔 `version.json`。
- 網頁在這些時候讀一次 `version.json`（加時間參數、`cache: 'no-store'`，GitHub Pages 的非 HTML 檔會快取 10 分鐘）比對：**每 5 分鐘**（`setInterval`，真的時鐘，不靠畫面更新；分頁在背景時不讀）、**切回分頁時**、**班級連線重新接上時**（孩子或熊熊老師的連線收到 `welcome`，而且這個網頁之前已經收過一次 `welcome`：伺服器部署完會斷線重連，通常就是剛更新；網頁剛打開的第一次連線不檢查）。開發模式不檢查。
- 版本號：GitHub Pages 的建置有 `GITHUB_SHA`；Zeabur 的建置環境不含 `.git`（`.dockerignore`），用建置時間。同一個提交重新建置也會提示一次（無害，重新整理一下）。
- 班級伺服器的靜態檔：`version.json` 不快取（和 `index.html` 一樣）。

## 2. 有新版時

- 畫面上方出現提示「🎉 遊戲更新了！」與「立即更新」按鈕（每個畫面都有，蓋在其他介面上面，不擋操作）。
- 規則是純函式 `updateMode(screen, { acting, duel, picking })` → `auto`（倒數自動更新）、`wait`（等）、`prompt`（只提示）：acting 是 `player.act` 有值（家具、遊樂器材、大型設施），duel 是和朋友對戰有邀請或進行中，picking 是佈置時拿著家具還沒放下。
- **孩子在安全的時候自動更新**：在島上走、建築的活動選單、獎章、百寶屋、標題與選角色畫面，而且**沒在用家具、玩遊樂器材或大型設施**、沒在和朋友益智對戰（含邀請中）時，提示上寫「10 秒後自動更新」倒數，時間到重新整理。
- **不安全的時候等**：答題、結算、益智遊戲館、坐在設施上（大型設施付了 5 金幣）、對戰中，提示寫「做完回到島上就會更新」，回到安全的地方才開始倒數。
- **大人的頁面只提示**：老師與家長的帳號頁、班級頁、家長區、熊熊老師進島、學校平板的教室頁，只有「立即更新」按鈕，不自動重新整理（可能正在打字或設定）。
- 按「立即更新」或倒數到：把現在的畫面記在 `sessionStorage`（重新整理還在、關掉分頁就沒了），重新整理後**回到原本的地方**（島上 → 島上、帳號頁 → 帳號頁、班級頁 → 班級頁；熊熊老師進島 → 帳號頁，再按一次進島；家長區要密碼，回標題畫面）。存檔、待上傳的操作都在裝置上，重新整理不會掉。網址上有加入班級、家長連結卡、信裡的連結時，那些先處理，不回原本的地方。重新整理後要先點一下畫面才有聲音（和剛打開網頁一樣）。

## 3. 分段（每段先寫會失敗的測試）

1. **規則**（純函式）：新舊版本比較、這個畫面與狀態是「自動」「等」還是「只提示」、重新整理後回到哪個畫面。
2. **建置**：版本號與 `version.json`；伺服器的快取標頭。
3. **畫面與檢查**：提示、倒數、立即更新、重新整理後回到原本的地方；連線重新接上時檢查。
4. **e2e**：假裝有新版（攔截 `version.json`）→ 島上倒數後自動重新整理並回到島上；答題中只提示、回到島上才倒數；帳號頁只提示、按了才更新。上線。

## 4. 實作紀錄（2026-10-13 完成，02:57 上線）

- **建置**（`vite.config.ts`）：版本號 `buildId()`（`GITHUB_SHA` → 本機 `git rev-parse` → 建置時間），寫進網頁 `__BUILD_ID__`（`src/buildId.d.ts`；開發模式是空的，不檢查），`versionFile()` 外掛輸出 `dist/version.json`（`{ id, builtAt }`）。伺服器的 `version.json` 不快取（`server/static.ts`）。
- **規則**（`src/update/updateRules.ts`，純函式，6 條單元測試）：`isNewVersion`、`updateMode`、`resumeScreenOf`。
- **檢查與套用**（`src/update/useUpdate.ts`）：`checkForUpdate`（加時間參數、`no-store`）、`startUpdateWatch`（5 分鐘、切回分頁）、`onServerWelcome`（孩子與熊熊老師的連線收到第二次以後的 welcome）、`applyUpdate`（記下要回到的畫面在 sessionStorage，重新整理）、`takeResume`（`App` 在網址參數處理完之後，還在標題畫面才回去；要回島上但沒有角色時回選角色）。e2e 用 `window.__game.update`（`check()`、`buildId`）。
- **提示**（`src/ui/UpdateBanner.tsx`，每個畫面都有）：「🎉 遊戲更新了！」、說明（`update-note`：N 秒後自動更新／做完回到島上就會更新／按「立即更新」換成新版）、「立即更新」（`update-now`）。安全時每秒倒數，變成不安全倒數重來。手機版排在上方一行下面。
- **測試**：`tests/update/updateRules.test.ts`；`tests/server/static.test.ts` 加 `version.json`；e2e `e2e/update-notice.spec.ts`（版本一樣不提示；島上倒數後自動重新整理回到島上、同一個角色；手機版提示不壓到上方的按鈕；答題中只提示不重新整理、回島上才倒數；帳號頁只提示、按了才重新整理回帳號頁）。
- **避免一直重新整理**：更新前把要更新到的版本號一起記在 sessionStorage；重新載入後網頁的版本還不是那一版（GitHub Pages 的 CDN 剛部署完約 10 分鐘還沒換完、學校的代理伺服器快取了舊網頁）就記成卡住（`isStuck`），這次載入只提示「新版還在傳過來，請過幾分鐘再按『立即更新』」，不再自動重新整理。
- **已知**：這個功能是這一版才有的，還開著舊版（沒有檢查功能）的人這一次收不到通知，要自己重新整理一次；之後的每一次更新都會通知。同一個提交在 Zeabur 重新建置（版本號是建置時間）也會提示一次。重新整理後要先點一下畫面才有聲音。
