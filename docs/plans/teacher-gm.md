# 老師 GM 與班級內容規劃

> 狀態：規劃中（2026-10-03）。第 12 節的待確認事項回覆後，再照第 11 節分期實作。
> 相關文件：`docs/plans/online.md`（線上版）、`docs/content-pack.md`（題庫包格式）、`src/content/editions/schema.ts`（版本包格式）。

## 1. 使用者的需求（2026-10-03）

原話：「老師要做成類似GM 跟其他同學造型不同，可以設定大家的版本 之後規劃容易更新題目及內容」

確認問題的回答：

- **班級版本**：老師統一，家長不能改。
- **老師造型**：熊熊老師的樣子。
- **GM 能力**：全班公告、集合、看到大家在做什麼、發獎勵（四項都要）。
- **內容更新**：上傳題庫包到班級、用試算表編題目、網頁上直接編題目、老師更新生字表／版本包（四項都要）。另外補充（原話）：「老師能控制進入班級島的題目來源 但家長學生也能自己開一個專屬島, 上面可由家長透過密碼改其他版本練習 且分數跟道具可以累積」

**合併解讀（待使用者確認）**：「家長不能改」只限**班級島**；**專屬島**由家長用家長 PIN 選版本；兩座島的分數、金幣、道具都累積在同一份進度。

## 2. 現況（2026-10-03）

- **教材版本**：每個角色的 `profile.curriculum`（國語版本、數學版本、學期），在家長專區「教材版本」選，班級帳號用 `curriculum` 操作同步到伺服器。選單的課本單元、段考模擬依它產生（`src/activities/resolve.ts`）。
- **家長 PIN**：4 位數，存在那台裝置的存檔（`save.parent.pinHash`），沒有跟雲端帳號同步；家長專區用 `PinGate` 把關。
- **題庫包、版本包**：只存在那台裝置的瀏覽器（`usePacks`、`useEditions`），換裝置要重新匯入。
- **老師**：只有管理頁（建立房間、成員清單、重設密碼、移出、開關加入／聊天／送禮、Google 綁定），不會進島。老師的權杖是 `teacher` 種類，沒有角色存檔。
- **即時連線**：只收孩子的權杖（`server/ws.ts` 的 `joinInfoOf`）。成員狀態有暱稱、外觀、稱號、位置、所在建築（`zone`，同學都看得到）。孩子的角色有 `cloud` 而且不在離線畫面時就會連線（`src/online/realtimeClient.ts`）。
- **熊熊老師**是 NPC（`src/world/Teacher.tsx`）：站在中央廣場；活動舞台上也有一隻會對答題結果做反應。
- **伺服器的請求大小上限**：`/api/*` 一律 1 MB（`server/app.ts` 的 `bodyLimit`）。

## 3. 兩座島：班級島與專屬島

### 3.1 班級島

- 加入班級的孩子在班級島上和同學同島、聊天、送禮；老師可以用熊熊老師的身分進島（第 5 節）。
- 題目來源由老師決定（第 4 節）。家長專區的版本設定對班級島無效，畫面顯示「班級島的教材版本由老師設定」。

### 3.2 專屬島：兩種讀法（待確認第 1 題）

| | (a) 同一個帳號的「自己玩」模式 | (b) 家長另開一個房間 |
| --- | --- | --- |
| 是什麼 | 班級帳號切換到自己的島：看不到同學，用家長選的版本與裝置上的題庫 | 家長像老師一樣另建一個房間（家庭島），兄弟姊妹可以加入、一起玩 |
| 進度累積 | 同一個帳號、同一份進度，自然累積 | 孩子在家庭島是另一個帳號；要累積，就得讓一個孩子在兩個房間共用同一份進度（帳號合併或共用存檔） |
| 要改的 | 前端加「班級島／我的島」切換；選單依所在的島決定版本與題目來源 | 帳號要能屬於多個房間：帳號、權杖、存檔同步、禮物、老師管理頁的資料模型都要改 |
| 工程量 | 小（約一期） | 大（好幾期，現有的雲端存檔要重新設計） |

**建議 (a)**：「家長用密碼換版本練習、分數道具累積」(a) 就能做到。家庭一起玩，可以由家長另外建一個房間（現在就能做），只是進度分開。

(a) 的細節（建議值）：

- 島上的按鈕切換「🏫 班級島」與「🏝️ 我的島」，記住上次的選擇。
- 在專屬島時看不到同學、不能聊天和送禮，但仍收得到老師的公告與集合；集合時提示「老師請大家回到班級島」，按了就切回去。老師的清單上顯示這個孩子「在專屬島」。
- 沒加入班級的角色（單機）照舊只有自己的島，不受影響。

## 4. 班級島的題目來源（老師控制）

- **教材版本**：老師在管理頁選國語版本、數學版本與學期（自動或指定），存在房間上（`rooms` 新增欄位）。班級帳號在班級島一律套用；孩子的 `profile.curriculum` 保留給專屬島用。
- **題目來源開關**（老師設定）：
  - 跟著課本（班級版本的課次單元、段考模擬）
  - 各主題活動（內建出題器的活動）
  - 班級題庫（第 7 節，老師上傳或編輯的題庫包）
  - 家長在裝置上匯入的題庫：班級島上預設不顯示，只在專屬島顯示（待確認第 2 題）
- **進度**：不管在哪座島答題，星星、金幣、錯題本、獎章都記在同一個帳號。

## 5. 熊熊老師進島（GM 模式）

- **入口**：老師管理頁的「以熊熊老師進島」。教室電腦接投影機也能用，全班看到同一座島。
- **外觀**：熊熊老師的模型（`Teacher.tsx`），名牌是金色的「熊熊老師」。
- **NPC**：老師在班級島上時，廣場上的 NPC 熊熊老師隱藏，大家看到的是真的老師在走動；老師離線就恢復。活動舞台上的熊熊老師照舊。
- **技術決策：即時連線的成員分成孩子與老師兩種，不給老師假的角色存檔。** 老師不答題、不存進度、不買東西；給老師一份假存檔，同步、商店、獎章、送禮都要特判，反而容易出錯。具體做法：
  - WebSocket 的 `hello` 接受老師權杖：以 GM 身分加入該房間。
  - `MemberState` 加 `role: 'kid' | 'teacher'`；老師的外觀固定是熊熊老師，不做外觀檢查。
  - 前端的 GM 模式不需要角色存檔：顯示島、可以走動；隱藏金幣、商店、建築入口與送禮；顯示 GM 工具列。
  - 同一個房間有兩台老師裝置同時進島時，都以熊熊老師出現（少見，先不特別處理）。

## 6. GM 能力

1. **全班公告**：老師輸入一句話（最多 60 字）。班級島上每個孩子的畫面上方出現大字幕，公頻也記一則「熊熊老師：…」，並用裝置語音朗讀（老師自由輸入的句子沒有預錄語音）。孩子正在答題時只顯示字幕、不朗讀，以免蓋過題目。每 10 秒最多一則。
2. **集合**：老師按「集合」，在島上的孩子就傳送到老師身邊排成一圈。在建築裡或正在答題的孩子收到通知卡「熊熊老師請大家集合」，按「過去」才傳送，不打斷答題。老師也可以在清單上點某個孩子，瞬間移動到他旁邊（只限在島上的孩子）。
3. **看到大家在做什麼**：孩子的裝置回報目前在做什麼（在島上、在哪棟建築、正在玩哪個活動），伺服器**只轉給老師的連線**；同學之間維持現況，只看得到在哪棟建築（待確認第 3 題）。老師畫面有全班清單：線上或離線、在哪裡、正在玩什麼，以及管理頁原本就有的學習摘要。這份狀態只放在伺服器的記憶體，不寫入資料庫。
4. **發獎勵**：老師對一位孩子或全班發金幣（每次 1～50 枚）或貼紙（現有 8 種之一）。伺服器在交易裡直接改孩子的存檔（`rev` 加 1），並記一筆獎勵紀錄。線上的孩子立刻收到卡片「熊熊老師給你 10 枚金幣！」，離線的孩子下次上線時收到。**不沿用送禮的「待收下／退回」流程**：老師的獎勵沒有扣款方，也不需要拒絕；只借用禮物卡片的畫面。

## 7. 內容更新

1. **上傳題庫包到班級**：老師在管理頁上傳 JSON（`docs/content-pack.md` 格式，伺服器用同一份 zod 檢查），存在伺服器。班級帳號登入或連線時自動下載，挑戰塔出現「班級題庫」分組。可以停用、刪除、改名。上限：每包 2000 題、每班 30 包、單次上傳 4 MB（題庫上傳的路由另外放寬 `bodyLimit`）。
2. **用試算表編題目**：提供範本（欄位：科目、題型、題目、選項 1～6、答案、單位、解說、課綱代碼、出處），老師在 Google 試算表或 Excel 填好、匯出 CSV，在管理頁上傳。前端把 CSV 轉成題庫包格式，先顯示預覽與錯誤（第幾列、哪一欄），確認後才上傳。第一版支援單選、數字、排順序、描寫四種題型；撥時鐘、付錢之後再加。
3. **網頁上直接編題目**：管理頁的「班級題庫」可以新增、修改、刪除題目；依題型顯示不同欄位，旁邊即時預覽題目的樣子，存回伺服器。
4. **老師更新生字表／版本包**：老師上傳版本包 JSON（`src/content/editions/schema.ts` 格式）到班級，班級版本的選單就多出這個版本；用相同 id 可以覆蓋內建版本（修正學校用的年度差異）。

共同注意：

- 自訂題目沒有預錄語音，改用裝置語音；新出現的國字沒有注音字型（現有限制，`docs/content-pack.md` 已寫）。
- 專案規則要求每題都有 `indicators` 與 `source`：試算表與編輯器都要有這兩欄（課綱代碼可以留空；出處預設「班級自編」）。
- 題目內容是老師自編，不要整份照抄出版社的教科書（`docs/content-pack.md` 已寫）。

## 8. 安全與隱私

- GM 的操作（公告、集合、獎勵、上傳內容、設定版本）只有老師權杖能做，伺服器檢查。
- 公告由老師自由輸入，不經過短句盤；限制長度與頻率。
- 孩子「正在玩什麼活動」只送給老師，同學看不到彼此在練什麼。
- 新增的資料：班級的版本設定與題目來源開關、班級題庫與版本包（老師的內容）、老師的獎勵紀錄、孩子目前在做什麼（只在記憶體）。
- **這些功能上線前，`public/privacy.html` 要一起更新**：寫明老師看得到孩子目前在做什麼、獎勵紀錄、班級題庫，並更新日期。Google 品牌驗證會比對政策和實際行為，政策不能比功能晚。

## 9. 伺服器介面與資料表（草案）

HTTP：

- `PATCH /api/teacher/room`：多 `curriculum`（版本與學期）、`sources`（題目來源開關）
- `GET /api/class/content`：孩子取得班級的版本設定、來源開關、班級題庫與版本包（帶版本號，沒變就不重傳）
- `POST`／`PATCH`／`DELETE /api/teacher/packs[/:id]`：班級題庫
- `POST`／`DELETE /api/teacher/editions[/:id]`：版本包
- `POST /api/teacher/rewards`：`{ to: 帳號 id 陣列或 'all', coins?, sticker? }`

WebSocket 新訊息：

- 孩子 → 伺服器：`{ t: 'doing', activity }`
- 老師 → 伺服器：`{ t: 'announce', text }`、`{ t: 'summon' }`
- 伺服器 → 孩子：`{ t: 'announce', text }`、`{ t: 'summon', x, z }`、`{ t: 'reward' }`、`{ t: 'content' }`（班級內容更新了，重新下載）
- 伺服器 → 老師：`{ t: 'doing', id, activity }`

資料表（migration 第 4 版）：

- `rooms` 加 `curriculum jsonb`、`sources jsonb`、`content_rev integer`
- `class_packs`（id、room_code、title、pack jsonb、enabled、created_at、updated_at）
- `class_editions`（room_code、id、edition jsonb、updated_at）
- `rewards`（id、room_code、to_id、coins、item_id、seen、created_at）

## 10. 測試

- **單元（純函式）**：班級島與專屬島的有效版本、題目來源篩選、CSV 轉題庫包（含錯誤列）、獎勵套用到存檔。
- **伺服器（PGlite）**：老師設定版本、上傳題庫包（格式錯、太大、不是老師）、獎勵（交易、離線收到）、WebSocket 的老師加入、公告、集合、`doing` 只轉給老師。
- **e2e**：老師進島（熊熊老師出現、NPC 隱藏）、兩台裝置的公告與集合、班級題庫出現在挑戰塔、試算表匯入、切到專屬島後看不到同學。

## 11. 分期（建議）

| 期 | 內容 | 說明 |
| --- | --- | --- |
| G0 | 班級教材版本 | 老師在管理頁設定版本與學期；班級帳號在班級島套用；家長專區對班級帳號顯示「班級島由老師設定」。不論專屬島怎麼選都要做，也最小 |
| G1 | 專屬島 | 依第 12 節第 1 題的選擇；(a) 約一期，(b) 另外估 |
| G2 | 熊熊老師進島、全班公告、集合 | 即時連線加老師成員、GM 模式 |
| G3 | 看到大家在做什麼、發獎勵 | 老師的全班清單、獎勵卡片 |
| G4 | 班級題庫與版本包、題目來源開關 | 上傳 JSON、班級島只顯示老師控制的來源 |
| G5 | 試算表匯入 | CSV 範本與預覽 |
| G6 | 網頁題目編輯器 | 依題型的表單與即時預覽 |

每一期照 T3 流程：先寫會失敗的測試、實作、e2e、更新文件（隱私權政策、本文件、`CLAUDE.md`）。
